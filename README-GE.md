# დარჩა — სამშენებლო მასალების ყიდვა-გაყიდვის საიტი

**მეორე ვერსია (MVP v2)** — ქართულ, ინგლისურ და რუსულ ენებზე მომუშავე, მობილურზე ადაპტირებული განცხადებების საიტი. კონცეფცია: რემონტისა და მშენებლობის შემდეგ დარჩენილი ახალი ან მეორადი მასალების ყიდვა-გაყიდვა მთელი საქართველოს მასშტაბით.

## რა მუშაობს უკვე

- **3 ენა:** 🇬🇪 ქართული, 🇬🇧 English, 🇷🇺 Русский. გადართვა საიტის ზედა ზოლში, ენის არჩევანი ინახება ბრაუზერში და გვერდის გადატვირთვისასაც რჩება. ნათარგმნია გვერდის ტექსტები, კატეგორიები, ქალაქები, ფილტრები, ფორმები, შეცდომები, საინფორმაციო წესები და საჩვენებელი განცხადებები. მომხმარებლის მიერ დაწერილი განცხადების სათაური/აღწერა ავტომატურად არ ითარგმნება (გამოჩნდება თავდაპირველ ენაზე).

- კატეგორიები (12), ძებნა, ქალაქის / მდგომარეობის ფილტრები, დალაგება, განცხადების დეტალური გვერდი.
- განცხადების დამატება: სახელი, ფოტოები (4-მდე), ფასი, რაოდენობა, კატეგორია, მდგომარეობა, ტელეფონი, ქალაქი, აღწერა.
- გამყიდველთან პირდაპირი ზარი და WhatsApp (ნამდვილ განცხადებებზე).
- რჩეულები, ჩემი განცხადებები, გაყიდულად მონიშვნა და წაშლა.
- რესპონსიული დიზაინი, PWA, SEO მეტამონაცემები და GitHub Pages-თან თავსებადობა.
- ორი რეჟიმი: *დემო* და *საჯარო Firebase*.

## 1. GitHub Pages-ზე სწრაფი გამოქვეყნება

1. შექმენი ახალი **Public** რეპოზიტორია GitHub-ზე (მაგალითად `darcha`).
2. ZIP-დან ატვირთე **შიგნით არსებული ფაილები**, ისე რომ `index.html` რეპოზიტორიის ძირითად საქაღალდეში იყოს და არა ZIP-ის სახით.
3. GitHub → `Settings` → `Pages` → `Build and deployment` → `Deploy from a branch`; აირჩიე `main` და `/ (root)` → `Save`.
4. საიტი გაიხსნება `https://USERNAME.github.io/darcha/` მისამართზე (USERNAME შეცვალე შენით).
5. პირველ ეტაპზე საიტი დაიწყება დემო რეჟიმში. დემოში არის **გამოგონილი საჩვენებელი განცხადებები**, რომ დიზაინი და ფუნქციები შეგეძლოს შეამოწმო. შენ მიერ დამატებული დემო განცხადებები მხოლოდ ამ ბრაუზერში ინახება — **სხვა მომხმარებლები ვერ ნახავენ**.

## 2. ნამდვილი საერთო ბაზის ჩართვა Firebase-ით

1. შედი https://console.firebase.google.com/ და შექმენი ცალკე პროექტი (ეს სხვა პროექტებს არ შეეხება).
2. პროექტში შექმენი **Web App** და დააკოპირე Web App-ის კონფიგურაცია.
3. GitHub-ში გახსენი `config.js` და `firebaseConfig` ობიექტში ჩასვი შესაბამისი `apiKey`, `authDomain`, `projectId`, `storageBucket`, `appId`. **არასოდეს ჩასვა სერვისის ანგარიშის private key**.
4. Firebase Console → **Authentication** → `Sign-in method`: გააქტიურე **Google** და **Email/Password**. Authentication → `Settings` → `Authorized domains`: დაამატე `USERNAME.github.io`.
5. Firebase Console → **Firestore Database** → `Create database` (რეკომენდებულია Production mode), და მერე `Rules`-ში ჩასვი ფაილ `firestore.rules`-ის ტექსტი → `Publish`.
6. Firebase Console → **Storage** → დააყენე default bucket. `Rules`-ში ჩასვი `storage.rules` → `Publish`.
7. **მნიშვნელოვანი:** Firebase Cloud Storage-ისთვის 2026 წლიდან საჭიროა **Blaze (pay-as-you-go)** გეგმა და დაკავშირებული გადახდის ანგარიში, მიუხედავად იმისა, რომ უფასო მოხმარების ლიმიტებიც არსებობს. დააყენე ხარჯების გაფრთხილებები (budget alerts). კოდში ფაილების 5 MB-მდე და 4 ფოტომდე შეზღუდვა ხელს უწყობს ხარჯის შემცირებას, მაგრამ აბსოლუტურ დაცვას არ იძლევა.
8. გამოქვეყნების შემდეგ Firebase რეჟიმი ჩაირთვება ავტომატურად: აღარ იქნება გამოგონილი განცხადებები; ნამდვილი მონაცემები გამოჩნდება ყველა ვიზიტორისთვის.

## 3. მნიშვნელოვანი უსაფრთხოების საკითხები საჯარო გაშვებამდე

- ეს არის **MVP**, არა სრულად მოდერირებული, მასშტაბური ბაზარი. Firebase Authentication-ის ანგარიში საჭიროა საჯარო განცხადების დასამატებლად. მნახველს ანგარიში არ სჭირდება.
- Firestore და Storage **წესები აუცილებელია**; არ დატოვო `allow read, write: if true` რეჟიმი.
- რეალურ გაშვებამდე დაამატე ადმინისტრატორის მოდერაცია, ანგარიშის/განცხადების გასაჩივრების გზა, სპამის საწინააღმდეგო შეზღუდვები, უფლებამოსილი ოპერატორის საკონტაქტო მონაცემები, საბოლოო Privacy Policy და Terms.
- გამყიდველის ტელეფონი საჯაროდ ჩანს. არ გააზიარებინო პოსტში პირადი მისამართები ან სხვა ზედმეტი პერსონალური მონაცემები.
- „TOP“ განცხადებების გადახდა ჯერ **არ არის ჩართული**. მომავალში შეიძლება ფასიანი წამოწევა 3–5 ₾, მაღაზიების რეკლამები და სხვა სერვისები, მათი რეალური დაყენებისა და ტესტირების შემდეგ.
- Firestore-ის პირველ ვერსიაში იტვირთება მაქსიმუმ 250 უახლესი ჩანაწერი და მერე ფილტრაცია ხდება ბრაუზერში. ზრდის შემთხვევაში საჭიროა სერვერული ფილტრაცია, გვერდებად ჩატვირთვა და ინდექსები.
- Firebase ფაილების ან დირექტორიების პირდაპირი ბმულები Firebase Storage-ზე საჯაროდ მისაწვდომია; მომხმარებლის ფოტოები არ გამოიყენო კონფიდენციალური ინფორმაციისთვის.
- Firebase-ის კონფიგურაცია საჯაროა (ეს ნორმალურია client SDK-სთვის); უსაფრთხოება დამოკიდებულია სწორი Rules-ზე, Auth-ზე, App Check-სა და ხარჯის კონტროლზე.

## კოდის სტრუქტურა

- `index.html` — გვერდები და ფორმები.
- `styles.css` — დიზაინი და მობილური განლაგება.
- `app.js` — UI, კატალოგი, ფილტრები, დემო რეჟიმი და განცხადების მართვა.
- `i18n.js` — სამენოვანი ინტერფეისი, ენების გადართვა და ტექსტების თარგმანები.
- `config.js` — საჯარო Firebase Web App კონფიგურაცია (თავიდან ცარიელია).
- `firebase-service.js` — Firebase Auth / Firestore / Storage მოდული, ირთვება მხოლოდ კონფიგურაციის შემდეგ.
- `firestore.rules`, `storage.rules` — ჩასასმელი უსაფრთხოების წესები.
- `manifest.webmanifest`, `service-worker.js`, `assets/` — PWA და ვექტორული კატეგორიის სურათები.

**ლოკალურად სანახავად:** გახსენი `index.html` ლოკალური HTTP სერვერით, მაგალითად `python -m http.server 8000`, შემდეგ `http://localhost:8000/`. GitHub Pages-ზე ეს ავტომატურად კეთდება.
